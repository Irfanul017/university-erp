4A. Working integration implemented (Student and Enrollment)
- This is the live relationship already working in the project code:
  Student.java -> @OneToMany(mappedBy = "student") private List<Enrollment> enrollments;
  Enrollment.java -> @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "student_id") private Student student;
- Meaning: one student can have many enrollments, each with a different semester, academic year, division, or roll number.
- This is the integration pattern other modules should follow when connecting to the student and enrollment flow.

4B. How to integrate with the student and enrollment modules
1. Create a student first through POST /api/students.
2. Copy the returned studentId UUID.
3. Use that studentId in the enrollment payload for POST /api/enrollments.
4. Fetch all students with GET /api/students.
5. Fetch student enrollments with GET /api/students/{studentId}/enrollments.
6. Fetch all enrollments with GET /api/enrollments.

This is the exact connection chain used by the project:
Student -> has many Enrollment records
Enrollment -> belongs to one Student

4C. SQL for student and enrollment tables
```sql
CREATE TABLE IF NOT EXISTS student (
    student_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    enrollment_no VARCHAR(100) NOT NULL UNIQUE,
    first_name VARCHAR(100) NOT NULL,
    middle_name VARCHAR(100),
    last_name VARCHAR(100) NOT NULL,
    gender VARCHAR(20),
    dob DATE,
    email VARCHAR(255) NOT NULL UNIQUE,
    phone VARCHAR(30),
    address TEXT,
    admission_date DATE NOT NULL,
    current_status VARCHAR(50) NOT NULL DEFAULT 'Active',
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS enrollment (
    enrollment_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    student_id UUID NOT NULL,
    semester INTEGER,
    academic_year VARCHAR(20) NOT NULL,
    roll_no INTEGER NOT NULL,
    division VARCHAR(10) NOT NULL,
    admission_type VARCHAR(50),
    enrollment_status VARCHAR(50) DEFAULT 'Active',
    start_date DATE NOT NULL,
    end_date DATE,
    exit_reason TEXT,
    final_cgpa DECIMAL(4,2),
    created_at TIMESTAMP DEFAULT NOW(),
    CONSTRAINT fk_enrollment_student
        FOREIGN KEY (student_id) REFERENCES student(student_id)
        ON DELETE CASCADE
);
```

- Use the studentId returned by the POST /api/students response.
- Then create an enrollment using that UUID in the enrollment request body.
- Current `studentId` and `enrollmentId` fields are UUIDs, not custom year-based numeric IDs.
